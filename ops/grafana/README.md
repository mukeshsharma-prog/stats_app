# Grafana dashboards — T-056 (DL-158)

Three dashboards, generated by `build-dashboards.py` into `dashboards/` and provisioned
read-only by the Compose `observability` profile:

```bash
docker compose --profile apps --profile observability up -d     # from docker/
open http://localhost:3000                                       # admin / admin, folder "Stats App"
```

| Dashboard | Rows | Owner |
|---|---|---|
| **Stats App — Writer** (`stats-app-writer`) | Throughput · Errors · Latency · Queues · Retention · Readiness | **Mukesh** — module rows (throughput, errors, latency, readiness); **Naman** — the Queues and Retention rows, which are the operational half of T-050/T-054/T-055 |
| **Stats App — Input** (`stats-app-input`) | Ingest (two doors) · HTTP · Q13b cycle-offset heatmap | **Mukesh** |
| **Stats App — PostgreSQL** (`stats-app-postgres`) | WAL archiver (RPO) · exporter reachability | **Naman** — the same owner as the restore runbook and D5 |

An owner is the person who is paged by the alerts that read the same series, and the
person who answers "what does this panel mean" — not the person who edits the JSON. Edit
`build-dashboards.py`, run it, commit both.

## The two rules every panel follows

1. **Shared gauges are aggregated with `max by (type)`, never `sum`** (DL-137). `queue_depth`,
   `dlq_depth`, `consumer_availability`, `queue_oldest_message_age_seconds`, the broker poll
   status and the retention gauges each describe ONE shared resource that every replica
   observes; summing N replicas reports N times the backlog. Per-replica **counters**
   (`records_*_total`) are genuinely per replica and are summed.
2. **A broker gauge is never shown without `broker_metrics_collection_success` beside it.**
   A failed poll writes `NaN` into every broker gauge by design, and a panel that hides
   `NaN` shows an empty queue. The Queues row has the stat panel at the top for that reason;
   the Retention row's gauges are `NaN` until the replica's first sweep (DL-156) for the same
   reason, and the "hours since the last sweep" panel is what says *never*.

Input series carry a `source` label since DL-151 (`internal` = Heimdal's door, `external` =
everyone else's) and are summed over it unless the panel is about the doors.

## What `check-dashboards.py` gates (CI)

* the committed JSON is exactly what the generator produces;
* **every metric name** in every panel expression *and* every alert rule in
  `ops/prometheus` is a series something exports — an application series whose base name
  is a string literal in `stats-writer` or `stats-input` main source (Micrometer suffixes
  applied), one composed name listed with its reason, or a named infrastructure series
  (`up`, Micrometer built-ins, the four `postgres_exporter` archiver series);
* no `sum` over a shared gauge.

A panel over a series that does not exist renders as an empty graph, indistinguishable
from "nothing happened". That is the one thing a dashboard must never say by accident, and
it is why the six series T-056's brief found asserted only at the registry are now asserted
at `/actuator/prometheus` by name (`ManagementSurfaceTest`), and why the gate and retention
series are registered per type at writer construction so they export at zero — or `NaN` —
from startup rather than appearing on their first event.

## Two series that appear on first event, by design

`records_dead_lettered_total{type,reason}` and `records_retried_total{type,tier}` are
created when a failure is first routed: the `reason` label is an exception class name and
cannot be enumerated in advance. Their panels are empty on a healthy replica; `dlq_depth`
is the durable view of the same fact.

## First render — 22 September 2026 (DL-160)

Rendered for the first time against the Compose stack with images built from the
current checkout (the ones running were two days and eleven commits old, which is the
first thing to check when a panel is empty). Every one of the 51 panel expressions ran
without error against the live Prometheus; the empties were the two first-event series
above and, before the rebuild, series the running image did not yet export.

Found: `pg_settings_archive_mode` was never exported — `archive_mode` is an enum and the
exporter's settings collector skips those — so the PostgreSQL dashboard's "archive_mode on"
stat was empty and the two alerts that read it were silent. `ops/postgres-exporter/queries.yml`
now exports it. `records_publish_confirm_seconds` (T-048) is on the Input dashboard since
DL-159.

The `stats-api` scrape target reads **down (401)** by design until T-038: its
`/actuator/prometheus` stays behind the bearer token (`ApiSecurityConfiguration`), and no
panel or rule reads a `stats-api` series yet.
